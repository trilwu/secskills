# Roadmap: learnings adopted from reverse-skill

Source: [zhaoxuya520/reverse-skill](https://github.com/zhaoxuya520/reverse-skill)
(MIT). Concepts only — all text in this repo is written from scratch in English.
The upstream repo's auto-merge pipeline, public contribute-back flow, and raw
payload dumps are deliberately **not** adopted; see `## Rejected` below.

Kept at repo root, not under `docs/` — `docs/` is generated by
`scripts/build_site.py`, which wipes it on every build.

Status legend: `[ ]` planned · `[~]` partial/rescoped · `[x]` done

## Phase A — architecture

- [x] **A1 `network_profile` vocabulary.** Four named egress modes (`offline`,
  `lab_only`, `authorized_target_only`, `unrestricted_lab`) added to
  `maintaining-engagement-state` record 1, referenced by skills that act
  against a target. Replaces prose-scattered egress constraints with one
  checkable enum.
- [x] **A2 Finding invariants.** Four checkable rules in
  `reporting-security-findings`: evidence non-empty; confirmed-status and
  low-confidence cannot coexist; reproduction runs without asking the author a
  question, or names the environment it cannot leave; a claim of obtained
  access or data has evidence of that specific claim. Failing findings move to
  the candidate worklist with a reason rather than being dropped.

  Note against the original plan: these are **not** enforceable by
  `scripts/validate.py`. That validator checks skills in this repo; findings
  live in engagement output the repo never sees. The invariants are therefore a
  self-check the skill instructs, not a CI gate.
- [x] **A3 tool-index discipline.** Folded into `maintaining-engagement-state`
  ("Across Engagements"): keep a machine-local inventory of tool path/version
  and MCP registration+liveness; never guess a path; distinguish *present* from
  *ready*. Shipped as discipline, not a generator script (user's call — keeps
  the repo documentation-only rather than maintaining cross-platform tooling).
- [x] **A4 field-journal discipline.** Folded into the same section:
  cross-engagement de-identified journal, indexed by scenario/technique/target
  trait, read before new work; seeded to avoid cold start; de-identify at write
  time; **local by default**, no upstream contribution path. Discipline, not a
  template generator.
- [x] **A5 `vetting-agent-extensions` skill.** New secskills-core skill (#24),
  public. Fills the gap `oss-intake-triage` explicitly excludes (agent skills
  and MCP servers). Covers context-loaded content as an injection surface,
  repo-shipped config that runs on startup, skill-stacking recall degradation,
  scope-drift inducement, and a four-tier adopt/narrow/sandbox/reject verdict.
  Unverified by design pending `verifying-skill-accuracy`.
- [x] **A6 Routing discipline.** `NOW`/`NEXT`/`ACT` step ordering and an
  explicit prohibition on answering "understood" without acting — added as a
  body rule in `authoring-security-skills`.
- [~] **A7 Fail-closed artifact pinning.** Rescoped: the intended targets
  (`php-webapp-vuln-lab`, `oss-intake-triage`) are user-level skills under
  `~/.claude/skills/`, not part of this repo. The principle is folded into
  `vetting-agent-extensions` (reject unpinned/`latest` downloads) instead.

## Phase B — reverse engineering coverage gaps

Ranked by value. Each goes through `authoring-security-skills` end to end:
plugin and tier choice, description, required sections, `ttp-index.json`
registration, eval cases including negative traps, then all validators. None
started yet.

- [x] **B1 JavaScript / frontend reversing** — signature-chain location in
  obfuscated bundles, webpack and sourcemap recovery, runtime sampling via
  CDP. Largest genuine gap; secskills has nothing on JS reversing today.
- [x] **B2 Memory-corruption exploit development** — ROP, heap grooming,
  mitigation bypass. `analyzing-binaries` reverses; nothing turns a crash into
  a working exploit.
- [x] **B3 Patch diffing for 1-day exploitation** — BinDiff/Diaphora workflow
  from patch to reachable primitive.
- [x] **B4 Thick-client desktop testing** — local storage, update channel
  integrity, IPC, client-side trust boundaries.
- [x] **B5 Browser extension reversing** — manifest, background workers,
  content-script boundary, extension-to-page privilege.
- [x] **B6 macOS / Mach-O reversing** — codesign, Objective-C and Swift
  recovery, TCC, notarization, Endpoint Security surfaces. Distinct from the
  existing `analyzing-ios-binaries`.
- [x] **B7 Custom protocol reversing** — recovering undocumented binary
  protocols from captures and clients.
- [x] **B8 Devirtualization** — custom opcode VMs and virtualized obfuscation,
  handed off from `unpacking-protected-binaries`.
- [ ] **B9 Hardware interfaces and SDR** — UART/JTAG discovery, secure-boot
  triage, RF replay feasibility in shielded lab conditions.

Deliberately skipped: one-skill-per-tool splits (`ida-reverse`,
`ghidra-reverse`, `radare2`) — secskills keeps `analyzing-binaries`
tool-agnostic on purpose, and per-tool skills fragment routing. EDR-bypass
research is out of scope for this repo.

## Rejected from the source

- **Auto-merged community content.** Unreviewed markdown merged into a repo
  that 17k agents load, gated by an English-only prompt-injection denylist in
  a predominantly Chinese-language repo. Currently fails closed only because
  GitHub restricts fork tokens, not by design.
- **Contribute-back to a public upstream.** Ships engagement learnings to a
  third-party repo with LLM-judged anonymisation as the only control.
- **Raw payload dumps.** Undefanged download cradles and credential-theft
  one-liners; quarantined on sight by Defender (verified locally — the clone's
  `payloader/raw/tools.json` was deleted mid-scan).
